## Defect corrections

- B1: the common source calculation reserves each requested rolled copy plus
  each exact permanent target not satisfied by permanent ownership. A granted
  copy cannot serve both roles. Suggestions, manual source approval, confirmation,
  and each subsequent spend use this calculation. Explicit exclusions and
  same-ID permanent-copy protection remain. Multiple owned qualities of one ID
  are excluded because ConfirmSpend accepts only an ID.
- B2: completion requires the original observed Orb offer, a choice submitted
  within that offer, one charge, closure of offer/host-pending state, and the
  exact matching ownership delta. Equal-content same-ID/same-quality data stays
  unresolved. A table identity change, charge decrement, source-removal snapshot,
  or uncorrelated positive selection notice cannot establish completion.
  Pending ownership and original exposure persist. There is no automatic retry.
  Same-ID/different-quality results retain a confirmable exact state delta.
  An adapter rejection before SelectPerk cannot establish a choice lifecycle,
  even if a later snapshot matches the proposed key. Confirmed/ambiguous calls
  and independently observed native choices are recorded separately from intent.
- Passive manual settlement uses an observation of the existing SelectPerk
  service and its pending ID on the exact offer. It does not replace a handler.
  If that observation cannot be made, missing evidence remains unresolved.
- I1: Recheck invokes passive reconciliation. A scoped passive guard also covers
  synchronous notifications during refresh. Passive settlement can record an
  already-submitted result, but cannot submit a new choice or spend.
- I2: Close keeps its existing behavior. The panel, confirmation, Help and guide
  disclose: Closing the window does not stop an approved run. Use Pause or Stop.
- N1: gated Echoes use the supplied integration's discovered/observed evidence
  and readiness marker. They also require a known boolean disable-state answer.
  Missing, failed or nonboolean optional capability results disable the affected
  action with a reason. Ungated targets remain available. IsSpellKnown is not a
  replacement for discovered Echoes.
  Loss or change of a live catalog entry disables that entry's Orb actions.
  The cached authoritative group/requirement metadata remains intact, so source
  loss cannot erase either tome gating or family-level copy protection.
- I3: normal Panel, Community projection/renderer, Journal, and role-picker
  consumers carry the corrected text. Raw policy reasons, saved keys, protocol
  values and gameplay decisions are preserved. See the 55-row terminology ledger.

## Focused offline validation

The original seven exact review probes and outputs remain unchanged in the
external correction evidence directory. All seven were rerun on the exact
P1.5 baseline. Their zero exit status demonstrates a defect or gap; it is not a
product safety result. Five fail-capable regressions were recorded red before
the product correction. The correction inventory has the original 42 scripts
plus twelve new scripts. The final source run is recorded in the delivery receipt.
The fresh independent review found two further edge cases in the first candidate:
pre-call selection rejection and loss of live catalog metadata (both availability
and protected-family consequences). Its three exact fail-capable probes were
copied as regressions; the preserved review receipts record their failures.

The original `orbs_same_echo` assumption that a new equal-content table proves
same-quality completion was replaced with a required unresolved assertion and
an actual different-quality same-ID result. Separate regressions require the
ambiguous same-quality outcome to remain pending across Recheck, Stop and reload.
The `orbs_ui` strict dimension check now covers the larger bounded window needed
for the full reason and Close notice. Its action assertions remain intact.
`role_selection` adds a real role-picker wording assertion. No safety assertion
was removed to obtain a pass.

Tests use the unchanged original review ctypes bridge and installed Windows
LuaJIT 2.1.1736781742 / Lua 5.1 DLL. They have isolated processes and 45-second
timeouts. No compatibility shims or native game services are used. The delivery
evidence supplies the final package run, exact hashes and focused independent
review result; this source note does not predeclare those outcomes.

## Remaining boundary

Real-resource Orb testing is not approved by this package. The supported API
does not expose a correlated revision or operation identifier that distinguishes
same-ID/same-quality completion from reordered stale ownership. An unresolved
operation can therefore remain blocked indefinitely; clearing its receipt or
refunding its allowance is not a recovery method.

Native capabilities, notification timing, ID-only quality-consumption behavior,
UI layout/hit-testing, and native resource safety remain unverified. The supplied
LoadoutPilot integration labels its selection-result signal uncorrelated and
requires other evidence. This correction does not invent stronger native proof.
No installation, WoW interaction, live SavedVariables access, Orb spending,
public distribution, or automatic native test is part of this delivery.
