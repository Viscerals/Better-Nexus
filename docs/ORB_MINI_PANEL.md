# Optional Orb mini panel

Open **Mini panel** in the Orb window to show a movable 356 × 196 status panel. It starts hidden each session. Drag its title bar to move it; its position lasts until reload. It shares the selected Nexus style and palette. The difficulty / Soul Ash card is unchanged.

The panel shows run status, the reason, Orbs used against the approved maximum, pending operations and **rolled target copies** still missing. Missing data is shown as unavailable; zero rolled copies does not mean the entire build is complete. During local restore it shows loading and unavailable counts; the footer re-enables after local readiness. Lines do not wrap, and every nonempty line is available in full on hover, including short text that a wider client font clips.

Pause and Resume occupy separate fixed buttons. Each click reads status again, then calls the existing runtime action with its final checks. Resume retains the approved maximum and usage. Its outcome is read again after the action, because the runtime may immediately pause or end the run. An ordinary pending spend can resume; restored or selected operations and changed assignments retain their runtime restrictions. Stop prevents another Orb spend; an operation already submitted may still settle. **Open Orbs** opens the full window. Starting a run and approving its maximum remain in that full window.

While a run is paused, the reason line names what Resume would act on (the runtime's `resumeTarget`): the original operation a pending run continues, or the ready assigned Wishlist a settled run would use. An assignment that is restoring, loading, unavailable or unassigned is never named. The run's own reason stays complete in the line's tooltip. When Resume would use a different Wishlist than the run started with, the mini panel does not offer Resume: it asks you to review the new target in **Open Orbs**. There, **Review target** records a review of that exact Wishlist, and Resume becomes available. Review and **Cancel review** spend nothing. The review is cleared by a different Wishlist, by leaving that state or by closing the window.

M7: **Review target** and **Cancel review** act only on the target the button was drawn for. If a fresh read at the click shows another target, nothing is reviewed or cancelled, Resume stays withheld and the window says to check the target shown now. A target that changed during the run and came back to the run's own Wishlist still needs the review; it is called back, not new ("Target changed and is back…", mini "Paused - review the target in Open Orbs"). A paused run whose assigned Wishlist is not ready refuses a mini Resume with "Not resumed: the Wishlist is not ready." A paused run that no longer owns its action (released at a loading screen, or without its context) names no target: "Paused - this run can no longer resume", with Stop and a new approval as the way on. A restored receipt without a recorded approved maximum shows "maximum not recorded" instead of a number; the configured fallback still gates it.

The full Orb window and the main Nexus panel strip use the same model during a run. Pause and Resume are separate fixed buttons in place of the window's Start, and two fixed buttons on the strip, so a repeated press of Pause never becomes Resume. Start, including the two-step **Start new run** / **Confirm new run**, returns once the run is no longer active. All three surfaces use one usage vocabulary: Orbs used against the approved maximum, and pending for a requested Orb whose spend is not confirmed yet. The mini panel keeps its "X of Y approved" form; the window, strip and history use "X / Y approved". The earlier one-button entry points remain only as hidden programmatic controls with the same checks; no player can click them.

Close and Escape hide only this panel. An approved run continues; use Pause or Stop to change it. Reopening reuses the panel and clears its old action notice. Visible status refreshes four times per second; hidden status does no work. Showing, moving and closing the panel do not save settings or placement.

`tests/prototype/orb_mini_panel.lua` exercises the real handlers and Orb runtime through synthetic WoW/services, plus fault injection for stale, malformed, missing and failed reads. It tests pending Stop, repeated and nested clicks, tooltips and a geometry model. `tests/prototype/orb_target_review.lua`, `orb_fixed_pause_resume.lua` and `orb_recovery_layers.lua` exercise target naming and review, the fixed controls, and recovery and usage wording through the same real handlers. Native font pixels, client skins, keyboard Escape, actual dragging, double-clicks and server effects require an in-client check; offline tests and the SIMULATED preview do not establish those effects.
