# Optional Orb mini panel

Open **Mini panel** in the Orb window to show a movable 356 × 196 status panel. It starts hidden each session. Drag its title bar to move it; its position lasts until reload. It shares the selected Nexus style and palette. The difficulty / Soul Ash card is unchanged.

The panel shows run status, the reason, Orbs used against the approved maximum, pending operations and **rolled target copies** still missing. Missing data is shown as unavailable; zero rolled copies does not mean the entire build is complete. During local restore it shows loading and unavailable counts; the footer re-enables after local readiness. Lines do not wrap, and every nonempty line is available in full on hover, including short text that a wider client font clips.

Pause and Resume occupy separate fixed buttons. Each click reads status again, then calls the existing runtime action with its final checks. Resume retains the approved maximum and usage. Its outcome is read again after the action, because the runtime may immediately pause or end the run. An ordinary pending spend can resume; restored or selected operations and changed assignments retain their runtime restrictions. Stop prevents another Orb spend; an operation already submitted may still settle. **Open Orbs** opens the full window. Starting a run and approving its maximum remain in that full window.

While a run is paused, the reason line keeps the runtime's own reason, shortened to the line when it is long and complete on hover. What Resume would act on (the runtime's `resumeTarget`) is named on the rolled-copies line instead: `Rolled missing:` with the count (`?` when it is unavailable, never 0), then the target's name in quotes, `(unnamed)` for a Wishlist without a name, or `target ?` while the assigned Wishlist is not ready. The count keeps its meaning, the rolled target copies still missing at the latest check; it is not relabelled as the named target's progress. A long name is cut on a character boundary to fit an offline model of a doubled client font; hovering shows the complete count, the complete target and what the line means. That bound is a character count, not a native measurement, and no native fit of a full name or of the line's height is promised. A pending operation whose assignment changed and a record restored after a reload name no target: the state line says that a pending result must settle first, and **Open Orbs** shows the details and the Continue state, if any.

When Resume would use a new target, that is, a ready assignment that differs, by the runtime's current comparison, from the one the run is bound to (the one approved at Start, or the one a later Resume adopted), the mini panel does not offer Resume, also after a review. Its state line asks you to review the new target in **Open Orbs**; there, **Review target** reviews that exact target and Resume can then be offered. Review and **Cancel review** spend nothing.

The fixed Pause and Resume buttons of the full Orb window and the main Nexus panel strip, the target review, the window's recovery layers and the shared usage words are described in `docs/ORB_MEMORY_MODE.md` (User interface and local readiness). The mini panel keeps its "X of Y approved" form; the window, strip and history use "X / Y approved". Its pending line reads `Pending: 1 Orb requested, not confirmed yet` while a requested Orb's spend is not confirmed, and `Last Orb result is not settled` when no requested Orb is waiting but the last action's result has not settled; the second is not an unconfirmed request.

Close and Escape hide only this panel. An approved run continues; use Pause or Stop to change it. Reopening reuses the panel and clears its old action notice. Visible status refreshes four times per second; hidden status does no work. Showing, moving and closing the panel do not save settings or placement.

`tests/prototype/orb_mini_panel.lua` exercises the real handlers and Orb runtime through synthetic WoW/services, plus fault injection for stale, malformed, missing and failed reads. It tests pending Stop, repeated and nested clicks, tooltips and a geometry model. `tests/prototype/orb_target_review.lua`, `orb_fixed_pause_resume.lua` and `orb_recovery_layers.lua` exercise target naming and review, the fixed controls, and recovery and usage wording through the same real handlers. Native font pixels, client skins, keyboard Escape, actual dragging, double-clicks and server effects require an in-client check; offline tests and the SIMULATED preview do not establish those effects.
