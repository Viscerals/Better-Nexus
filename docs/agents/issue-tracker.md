# Issue tracker: GitHub

Repository: `Viscerals/Better-Nexus`
Issues: https://github.com/Viscerals/Better-Nexus/issues
PRs as a request surface: **off**

GitHub Issues hold durable public bug, compatibility, feature and architecture requests. Use the existing authenticated `gh` CLI or authorized GitHub tools; this configuration requires no new software, tracker or automation.

## Read and write

- Resolve a bare `#<number>` against this repository. Check whether the item is an issue or PR before acting; automatic triage discovery covers issues only. An explicitly requested PR can still be reviewed or triaged.
- Read the complete request, comments, labels and prior evidence before proposing a disposition. Search for an equivalent issue and an existing implementation before creating work.
- Use `Refs #<number>` in a PR. Use a closing keyword only when the PR verifiably fixes that issue's own acceptance criteria.
- Label readiness is advisory. `ready-for-agent` does not dispatch work, authorize editing, bypass review, or change release/tester gates. Execution remains with the active task's approved owner and scope.
- Preserve existing issue text, history, labels and milestone assignments except for explicitly authorized changes. Apply triage only to the requested items.
- Keep private client exports, player data, SavedVariables, diagnostics and temporary execution artifacts out of public tracker content. Follow `AI_POLICY.md` and `SECURITY.md`.
- Triage-generated comments and issues start with `> *This was generated by AI during triage.*`

## Evidence and completion

A bug is closed as fixed only with evidence that satisfies its stated acceptance criteria on the accepted source. Record the commit and tested behavior, and separate merged source, published package and native validation status. Offline passing tests do not settle a native-only criterion. Rejected or duplicate requests need a reasoned maintainer disposition.

Follow `CONTRIBUTING.md` for branches, validation and PR evidence, and `RELEASE_SECURITY.md` for packaging and publication. Labels, a setup approval and passing offline checks confer no merge, publish or live-game authority.
