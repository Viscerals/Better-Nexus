## P1.1 update

A shared exact-active lock-evidence resolver now runs before Wishlist editing
and assignment, preserves counted 79+6 targets, and gives specific pending
reasons. A new 96-assertion regression covers positive, malformed, stale, and
read-only controls plus save/reopen. This does not claim the native report is
resolved. Only the two evidence-handling runtime owners changed.

## P1.2 update

Startup initializes evidence once per bound source/admission, preserves its
per-pump validation, and releases local controls after real Store readiness.
Community/Leaderboard/Sync/DPS wait for shared preparation separately. The
shared loading window does not start imports or claim empty data; local UI
can be used while it waits. See STARTUP_FIX_REPORT.md for measured comparisons,
retained limits, exact startup tests, and the explicit non-native runtime.

This does not make the full background catalog work instant or promise a
specific in-game startup time. The P1.1 locked-Wishlist hotfix and all planner,
transport, settings, and exact-evidence semantics remain included.
